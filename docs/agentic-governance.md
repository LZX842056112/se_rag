# 知识治理操作说明

查询证据、用户反馈和候选答案具有不同用途。用户反馈不能作为事实来源。模型输出的来源 ID 必须通过服务端校验。

缺口有四类。`retrieval_miss` 表示检索遗漏。`reading_miss` 表示阅读遗漏。`generation_error` 表示生成错误。`knowledge_missing` 表示知识缺失。只有最后一类进入 FAQ 生成。没有明确的知识缺失证据时，默认归入检索遗漏。

候选必须记录实际读取的分块 ID。生成器只能选择本轮上下文中的 ID。服务端重新读取原文，并检查产品、文档版本、有效期和正文摘要。模型不能提供权威的版本字段。

审批保留现有 `(bool, message)` 返回格式。外部状态继续使用 `draft`、`active`、`deprecated` 等值。内部 `publication_status` 表示发布进度。只有内部和外部状态都为 `active` 的条目可以召回。未迁移的旧条目不能召回。

审批先检查答案支持关系。原文包含完整答案时，检查直接通过。其它答案调用接地性检查器。评分必须有限，且不小于 `EVOLUTION_GROUNDEDNESS_MIN`。无法评分时，拒绝发布。检查器使用完整来源正文。

人工补充答案时，必须同时补充来源。调用 `approval.service.edit(..., source_refs=[...], item_names=[...])`。系统重新读取来源并保存版本。编辑已发布内容会先撤回旧内容。再次审批后，系统发布新版本。

发布任务存入候选集合对应的 `_publication_tasks` 集合。任务主键包含候选 ID、内容版本、内容摘要和索引版本。Mongo 主键保证任务唯一。任务有 120 秒租约。索引写入使用确定性 ID。失败后，任务保留错误原因和重试次数。重试间隔按指数增加，上限为一小时。进程重启后，工作线程可以领取租约已到期的任务。

后台循环调用 `run_publication_tasks()`。运维程序也可以调用此函数。重复审批会继续处理同一发布任务。索引完成前，候选保持不可召回。向量 ID 包含发布版本，不覆盖其它版本的 ID。

撤回先修改 Mongo 状态，再删除索引。删除失败时，持久化任务继续重试。召回在返回结果前读取 Mongo，并重新校验来源。索引中残留的旧向量不能绕过这个检查。Mongo 或来源存储不可用时，FAQ 召回返回空结果。

替换或删除源文档前，调用 `invalidate_document(doc_id, version=None)`。省略版本时，系统撤回该文档的全部派生 FAQ。指定版本时，系统只撤回依赖该旧版本的 FAQ。导入程序必须在写入新正文前调用此接口。写入开关关闭时，接口不修改数据。

迁移默认只报告。运行 `python -m app.evolution.governance` 查看数量。运行 `python -m app.evolution.governance --apply` 添加治理字段。迁移不删除候选，也不修改外部状态。所有旧记录进入 `review_required`。迁移不会自动信任旧答案或旧来源。

`recall_enabled()` 控制 FAQ 读取。`writes_enabled()` 控制后台知识写入。未配置独立开关时，两者使用旧的 `evolution.enabled`。离线评测应关闭写入，并使用隔离资源。调用 `approved_faq_snapshot()` 保存已发布内容摘要、内容版本、索引版本和来源版本。比较实验必须使用同一份快照。

本实现没有增加图索引或句子索引。当前发布目标是现有 FAQ 向量索引。后续增加索引时，必须扩展发布任务，并在全部目标完成后激活候选。
