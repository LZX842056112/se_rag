# Agentic RAG 运行说明

本轮实现保留旧查询模式。没有自动提交、推送、部署或启用生产灰度。

## 模式与预算

默认 `RAG_MODE=legacy`、`RAG_GRAY_PERCENT=0`。在独立测试环境启用新模式时，设置 `RAG_MODE=agentic`、`RAG_GRAY_PERCENT=100`。线上按会话 ID 的稳定哈希选择灰度，不按每次请求随机选择。回退时将 `RAG_MODE` 改回 `legacy` 并重启服务。

`RAG_POLICY_VERSION` 标记策略版本。`AGENT_LLM_MODEL` 留空时复用回答模型；设置后仅用于动作选择和证据检查，答案仍使用回答模型。评测模型继续要求明确设置 `EVAL_LLM_MODEL`。

默认限制：`AGENT_MAX_TOOL_CALLS=4`、`AGENT_MAX_WEB_CALLS=1`、`AGENT_MAX_REPAIRS=1`、`AGENT_MAX_CONTEXT_TOKENS=8000`、`AGENT_TIMEOUT_SECONDS=60`。首次检索计入工具预算。内部来源复核另计次数和耗时，也受同一截止时间限制。

`AGENT_TOKENIZER_PATH` 只读取本地 tokenizer，不下载模型。没有 tokenizer 时，按 UTF-8 字节数保守限制上下文，并记录 `utf8_bytes_upper_bound`。这通常会比 token 上限更早停止。

关键词匹配只扫描确认产品范围内最多 `AGENT_KEYWORD_SCAN_LIMIT` 条数据，默认 500。多一条即返回不可用状态，不扩大全库范围。邻块窗口 `AGENT_NEIGHBOR_WINDOW` 默认 1，最大 2。

## 查询行为

新模式先做一次直接检索。模型检查问题是否被证据完整支持，再选择检索、阅读、回答、澄清或转人工。重复动作、连续两次没有新证据、无效动作重试失败和预算耗尽都会停止。

正文读取校验产品范围与版本。答案生成前和检查通过后再次核验来源。文档更新、FAQ 撤回或政策过期时，不发送旧证据草稿。

模型草稿检查通过后才发送答案 delta；之前只保留内部动作记录。首字延迟可能增加。最终事件和历史保存沿用原接口，不输出模型私有推理。

HTTP 模型、Milvus、Mongo 和联网请求使用实际请求超时。进程内 BGE 模型加载与推理是同步计算，不能被网络超时中断；返回后会检查截止时间，并拒绝发送超时草稿。首次加载时间应单独测量，部署时应预热模型。

## 知识写入与评测

`EVOLUTION_RECALL_ENABLED` 控制已审批 FAQ 读取，`EVOLUTION_WRITE_ENABLED` 控制进化写入。未设置时沿用原 `EVOLUTION_ENABLED`。测试可开启读取，同时关闭写入、定时任务和自动调参。

新模式默认不自动调参。知识发布仍需人工审批和来源核验。缺少可核验来源的旧记录需要复核，不能自动成为可信事实。

知识治理、迁移与撤回见 [知识治理说明](agentic-governance.md)。基线准备和对照运行见 [评测说明](agentic-evaluation.md)。

40 条答案和 200 条意图样本仍为草稿。新增复杂样本也是草稿，不得自动改为人工已复核。真实评测只在独立 `eval_` 资源上执行，并且必须显式允许外部调用。

## 上线前的独立验收

先完成题库复核，再固定语料、已审批 FAQ、回答模型、评审模型和策略配置。比较逐题质量、评分覆盖、失败率、总时延、首字时延和费用。未知费用保持空值。

质量和延迟门槛应根据真实基线确定。当前代码及模拟测试不能证明质量提升，也不能替代生产灰度验收。没有完成这些验收时，保持旧模式。
